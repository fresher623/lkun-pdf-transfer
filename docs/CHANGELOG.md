## 1.0.2 / versionCode 3：应用内全选与批量导入（2026-10-27）

历史主应用名称为“纸间 · 图片转PDF”。

### 功能修改

- 主入口通过系统 `OpenDocumentTree` 选择具体目录，再在应用内展示图片。
- 顶部固定显示“全选 / 取消全选”，底部显示“导入已选 N 张”，支持一次导入 1～500 张，可继续追加且任务总数最多 500 张。
- 列出所选目录当前层的图片，不递归子目录；按文件名自然排序，同名条目保持稳定顺序。
- 超过剩余额度时先明确确认允许的数量，不静默截断；超 10,000 项目录明确报错。
- 保留系统文件逐张多选和 Photo Picker 辅助入口，说明系统相册本身可能存在单次选择上限。
- 修正快速连续勾选的额度检查；旋转时保留勾选状态，导入或校验失败时同步收起选择页。

### 验证与测试支持

- 文件夹最终四项仪器测试通过，实际点击“全选 → 导入已选 500 张”，验证条目有效性、ID 唯一、名称和顺序，以及原运行时图片 / 结果前后相等。
- 该套件使用预授权合成目录及微小 PNG，耗时 4.488 秒；此数字不是 500 张 12MP 转换耗时，也不代表个人目录的系统授权已测试。
- 500 张 4000×3000 合成 JPEG 连续转换三轮完成，耗时分别为 **319.554 / 208.408 / 130.215 秒**，每份 500 页、153,891,616 bytes。
- 最终留存 PDF 完成独立严格解析、500 页顺序条码和横向 A4 校验、首中末渲染及 SHA-256 匹配。
- 增加逐页 Java / native / PSS / RSS 记录、外部内存采样和合成证据镜像；镜像仅包含测试文件。
- 测试夹具改为独立 Java provider、同步授权桥和受控目录预授权；测试进程使用设备端持久运行，控件查找限定本应用并改为 BFS。历史失败与中断记录完整保留。

**验收限制：**首轮 319.554 秒超过五分钟目标。测试期间观察到系统冻结和 CPU 停顿，并使用普通前台 Intent 辅助；没有量化扣除冻结时间，也不把超时全部归因于冻结。真实相机组、4 GB 设备、完整系统 SAF / 目录授权、熄屏后台、取消最坏时延及连续真实内存峰值仍待验证，不能认定完整 V1 通过。

## 1.0.1 / versionCode 2：单批导入与基础流程（2026-10-26）

历史主应用名称为“纸间 · 图片转PDF”。

- 建立 Kotlin / Compose 安卓工程，最低 API 26，离线运行；完成图片整理、旋转、排序、页面 / 质量设置、后台生成、预览、保存和分享流程。
- 使用逐页写入磁盘的 JPEG PDF 引擎、采样解码和独立页码区域，避免把整份 PDF 或全部原图累积到内存。
- 调整批量入口为系统文件多选，可消费一次 500 个 URI 的选择响应；501 项必须显式确认后才导入允许的数量。
- 保存原始 URI 用于重复导入提示；不支持持久授权的源使用受控私有副本，坏图保留错误。
- 修复转换结束与新任务开始的竞态、源缓存清理与导入竞态、持久化空间错误，以及选择器 / 分享异常处理。
- 测试构建增加 `.benchmark` 包名后缀，与主应用隔离，保护既有草稿与结果。

历史验证：19 项核心 JVM 测试通过，100 / 300 / 500 页宿主 JPEG PDF 独立解析和渲染通过；隔离设备功能套件 6 项通过，单批 500 / 501 URI 导入另一次回归通过。较早“五项运行”实际为 4 通过、1 Assume 跳过，没有把输出中的 `OK (5 tests)` 误记为五项全部通过。

首次设备压力尝试完成 100 张和 300 张；500 张运行在第 326 页记录后被系统 `single-cleaner` 强停。退出记录没有提供 Java OOM 证据；此历史中断不因后来三轮完成而删除。

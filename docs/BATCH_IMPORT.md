# 一次导入 1～500 张图片

2026-10-26 用户补充：必须能够同时选择 500 张以内图片并一次性导入，不能只依靠多次追加累计。

1.0.2 将首页与整理页主入口改为“选择文件夹 · 批量导入”（`ACTION_OPEN_DOCUMENT_TREE`）。用户明确授予所选文件夹访问权后，应用只枚举当前层图片的名称和 URI，显示自己的复选列表、固定“全选 / 取消全选”和底部“导入已选 N 张”。选择器无需自带全选按钮；应用中按选定顺序逐张流式检查及导入，整批出现在同一任务中。

操作：选择图片所在的具体文件夹 → 在系统提示中允许访问 → 返回应用点击“全选” → 点击“导入已选 N 张”。只列出所选文件夹当前层；图片位于子文件夹时应直接选择该子文件夹。系统限制不能授权的根目录需改选具体子文件夹。

- 单次 1～500 张直接导入，任务已有图片时按剩余额度计算。
- 文件夹图片超过剩余额度时，点击“全选”先询问是否按自然文件名顺序选择前 N 张；逐项勾选也不能超过余额。取消不改原任务，不静默截取。辅助文件多选入口一次返回 501 张时仍先确认导入数量。
- 多次追加仍可使用，但不作为一次 500 张要求的替代方案。
- “系统相册”保留为辅助入口，其数量限制由设备决定。大量图片使用主批量入口。
- 转换仍每图一页、同一任务输出一个完整 PDF，再通过另存一次保存。

`BatchImportInstrumentedTest` 使用单次 500 / 501 个受控 Content URI 检查批次消费、顺序、稳定 ID、超限确认与取消；该自动化测试不等于已在所有设备和所有第三方文档提供方手动选择 500 张。完整结果以测试报告中的实测记录为准。

2026-10-27，1.0.2 在 vivo V2505A 的文件夹套件四项通过（`device-folder-bfs-test.log`）。其中通过实际按钮点击“全选 → 导入已选 500 张”，再由独立导入管线检查全部 500 项、唯一 ID 和顺序，且原任务图片与结果保持相等。此项使用预授权合成目录及微小 PNG，耗时 4.488 秒，不是 12MP 转换耗时，也未自动操作用户个人目录的系统授权界面。

另一次独立长测对 500 张 4000×3000 合成 JPEG 连续转换三次，均完成 500 页，耗时 319.554 / 208.408 / 130.215 秒。最终 PDF 的 500 页编号条码顺序和页面尺寸已独立检查。测试有前台辅助及系统冻结记录，首轮超过五分钟目标；真实相机图组、4 GB 设备和后台行为仍待验证。

## 使用步骤

1. 在图片工具首页点击“打开 PDF 合并 →”，进入独立页面；原图片草稿继续保留。
2. 点击“＋ 添加 PDF”，在系统文件界面选择文档。可以继续追加，任务最多 50 份；同一来源重复加入时会先询问，确认后整份文件的页面会再次出现在结果中。同名的不同文件不按名称去重。
3. 等待导入和检查完成，查看文件名、页数、大小及异常提示。可预览单份文件，用长按拖动或“上移 / 下移”调整文件顺序，也可移除条目或确认清空列表。
4. 至少添加两份有效 PDF 后输入输出文件名，点击“开始合并”。应用自动补齐 `.pdf`，本次顺序和名称在任务开始后锁定。
5. 结果按文件列表顺序拼接，每份文件内部页序保持不变。例如 A 有三页、B 有两页，输出为 A1 → A2 → A3 → B1 → B2。
6. 应用先生成并校验私有完整结果，再提供预览、另存、分享和其他应用打开。取消另存会保留完整结果，可以再次保存。

返回图片工具不会新建或清空另一类草稿。图片与合并共用重任务互斥门：一类工具正在导入、生成或另存时，另一类工具可以查看草稿，但不能同时启动受限制的操作。通知显示任务进度并提供返回和取消入口；通知取消使用对应任务标识，旧任务的按钮不能取消新任务。

## 支持内容与严格限制

候选实现使用 PdfBox-Android 复制 PDF 页面和关联对象，**不把页面截图后重建为图片 PDF**，也不直接拼接文件字节。对被接受的基础页面文档，按实现保留页面尺寸、页框、旋转及支持范围内的文字、字体、矢量和图片；本轮合成样本已通过内容保留检查；这不等于任意外部 PDF 兼容认证。合并不应用图片工具的 A4、边距、裁切、DPI、JPEG 质量或额外页码设置。

这不是通用 PDF 兼容器。当前检查采用保守白名单：文档根目录（Catalog）只允许 `Type`、`Pages`、`Version`。**带文档级 `Metadata`、`Lang`、`ViewerPreferences` 等设置的 PDF 也会被拒绝**，即使看起来只是普通文字页面；此处限制不等于 PDF 本身损坏。

| 文件内容或状态 | 首版行为 |
| --- | --- |
| 通过严格检查的基础静态页面 PDF | 按文件顺序合并全部页面，不提供页范围或单页编辑 |
| 加密、密码或权限限制 | 在解密处理前拒绝；没有密码输入或解锁功能 |
| 数字签名、认证或时间戳签名 | 拒绝，不宣称合并后签名仍有效 |
| AcroForm / XFA 表单、附件、文件包、命名交互项 | 拒绝 |
| 书签、自定义页标签、结构标签、注释、超链接或交互动作 | 拒绝，不静默删除后继续输出 |
| 可选图层、脚本、多媒体、外部文件或其他未支持的文档 / 页面字段 | 拒绝 |
| 损坏、截断、异常尾随数据、伪装文件或页树不一致 | 标记错误并阻止合并，不跳过坏页交付部分结果 |
| 页尺寸异常、边长超过 200 英寸、旋转不是 90° 整数倍或结构预算超限 | 拒绝 |

收到“不支持的文档级设置”等提示时，可在原软件中另存为更基础、无交互的页面 PDF 后重新选择；另存时应自行核对文字、外观及重要内容，不能保证任意导出方式都会进入本版支持范围。当前不承诺 PDF/A、PDF/UA、文件字节一致或输出大小等于输入大小之和。

## 文件、页数与资源预算

所有限制同时生效；MiB 为 1,048,576 字节。

| 项目 | 候选实现上限 |
| --- | --- |
| 开始合并的输入文件数 | 2～50 份 |
| 输入总页数 | 1～1000 页 |
| 单份输入文件 | 256 MiB |
| 全部输入文件合计 | 512 MiB |
| 合并输出 | 512 MiB，写入时检查 |
| 解析当前源文件的磁盘 scratch | 256 MiB |
| 目标文档的磁盘 scratch | 512 MiB |
| PDF 对象数量 | 每份最多 10 万，任务合计最多 20 万；另有对象图、数组和嵌套预算 |
| Java 堆检查点 | 已用堆越过上限 70% 后，至多触发一次 GC 复查，仍超限停止；1 秒内再次越线直接拒绝 |

scratch 是磁盘临时文件预算，源和目标可同时占用，合计上限为 768 MiB；它不包含私有输入副本、输出、已有结果及预留空间。应用会检查可用存储，但不能只按“输入总大小”估算所需空间。

70% 是离散检查点上的停止条件。为避免把等待回收的已释放源对象误判为持续占用，越线时至多触发一次 Runtime GC 并复查；仍超 70% 则停止，1 秒内再次越线直接拒绝，不循环等待。它不是全过程硬内存上限，也不是 Java / native / PSS / RSS 的实测峰值。解析对象仍可能随文档复杂度增长；上述预算不构成恒定内存、任意恶意 PDF 安全、4 GB 设备或后台稳定性认证。本轮 50 份 / 1000 页微小合成样本已取得实测耗时和 14 个阶段的离散内存数据，详细数值及限制见测试报告。

## 草稿、隐私与失败恢复

- 每份输入都会流式复制到应用私有 `files/merge-sources/` 后再处理，不为 PDF 保留长期 URI 授权。原 URI 仅用于私有草稿中的重复选择识别，不写入诊断日志。
- 合并草稿使用独立的原子 `merge-session.json`，不覆盖图片工具的 `session.json`。图片来源清理只处理图片工具登记拥有的授权，不撤销未知授权或目录树授权。
- 完整合并结果写入私有 `files/results/<任务ID>/`；预览和分享只访问受控文件，不对外暴露源副本目录，不覆盖或删除所选外部原文件。
- 取消、失败或下次启动会清理本次未提交的 `.partial` 和 scratch。已提交的完整结果与输入草稿继续保留；进程中断后需从头重试，没有断点续写承诺。
- 源副本不可用、空间不足或内存预算不足时，先处理提示再重试。已有完整结果应及时另存；当前没有完整的历史文件管理界面。
- 应用继续离线运行，不新增联网或整盘访问权限。禁用云备份和设备迁移；这不构成跨包或卸载后的数据迁移方案。

# l君の百宝箱：PDF 合并与工具整合计划

日期：2026-10-28（Asia/Shanghai）

状态：M0 / M1 的 1.1.0 PDF 合并已实现，25 项目标手机功能回归和受控 50 份 / 1000 页独立复核通过；用户随后反馈主包被 vivo 检测为恶意软件，原因未明，交付与推送暂缓。功能通过不等于安全审核通过。本文仍保留后续 M2 / M3 方案；百宝箱首页、更名及解混淆整合尚未实施。实际状态以 [迭代记录](ITERATIONS.md)、[测试报告](TEST_REPORT.md) 和 [安全排查](SECURITY_REVIEW.md) 为准。

## 1. 目标与现有基础

将现有图片转 PDF 工具逐步扩展为 **l君の百宝箱**，在一个应用中提供三个独立入口：

| 入口 | 用途 | 当前状态 |
| --- | --- | --- |
| 图片转 PDF | 全选并一次导入 1～500 张图片，整理后生成 PDF | 现有功能，继续保留 |
| PDF 合并 | 选择多份 PDF，调整文件顺序，合成一个 PDF | 1.1.0 已有独立界面与引擎，验证结果见测试报告 |
| 图片解混淆 / 混淆 | 迁入另一款应用的单图处理、预览、保存与分享 | 后续整合现有代码 |

当前 PDF 源码基线为 **1.0.4 / versionCode 5**，包名 `cn.local.imagepdf`，最低 API 26，使用项目发布签名。此前 1.0.2 的大图长测、1.0.3 的四项全选回归保留原版本归属，不能当作新增合并功能的验收结果。

另一款应用的已检查源码使用 `com.fanqie.hunxiao`、最低 API 29，核心为 Gilbert 像素置换。先迁移已经存在的单图功能；旧计划中的批量处理、多次操作等仍按后续需求管理，不当作已实现功能。

建议分两步交付：先做好 PDF 合并，再整合百宝箱首页与解混淆工具。全程本地处理，继续保持无账号、无广告、不上传用户文件。

## 2. 百宝箱首页与导航

建议首页按工具分类展示，避免把三个工具的参数混在同一页面：

```text
l君の百宝箱                         [当前任务]

PDF 工具
┌ 图片转 PDF ┐    ┌ PDF 合并 ┐
  最多500张          多份合一

图片工具
┌ 图片解混淆 / 混淆 ┐

[使用说明]                           [设置 / 关于]
```

- 每个工具拥有自己的草稿、参数、输入列表和结果；切换工具保留当前草稿。
- 返回首页不调用图片工具的“新建任务”，不清空其他工具的内容。
- 有任务运行时显示工具名、阶段和真实进度，点击后返回对应任务页。
- 首版只允许一个重任务运行。另一个工具可查看自己的草稿，但需要等当前任务结束后再开始处理。
- 首页和通知在整合阶段统一显示“l君の百宝箱”；工具内部继续显示“图片转 PDF”“PDF 合并”等明确名称。

## 3. PDF 合并独立界面

### 3.1 页面草图

```text
< 返回                 PDF 合并              [添加 PDF]

1  合同.pdf            12页 / 2.4MB    [预览] [移除]
   [上移] [下移]       可长按拖动调整文件顺序

2  附件.pdf             6页 / 1.1MB    [预览] [移除]
   [上移] [下移]

已选 2 份 PDF，共 18 页
输出名称：[合并文档.pdf                     ]

                     [开始合并]
```

第一版支持整份文件拼接：按列表顺序加入各文件的全部页面，文件内部页序保持不变。例如 A 有 3 页、B 有 2 页，结果必须为 **A1 → A2 → A3 → B1 → B2**。

### 3.2 使用流程

1. 从系统文件选择器一次选择多份 PDF，也可继续追加。
2. 逐份读取名称、实际页数、体积和可处理状态；读取中有状态提示，不阻塞界面。
3. 用拖动或上移 / 下移按钮调整文件顺序；可移除条目、预览单份文件。
4. 输入输出文件名。至少两份有效 PDF、检查完成且无阻塞错误后允许开始。
5. 点击开始后冻结本次文件顺序和参数，进入进度页。
6. 先在应用私有目录生成并校验完整 PDF，再进入结果页，提供预览、另存、分享和外部打开。
7. 取消另存仍保留应用内完整结果，可以再次保存。

同名的不同文件不按名称去重；同一 URI 再次添加先询问是否重复加入。每次加入都使用独立条目 ID，避免排序或移除误操作其他项。

建议第一版以 **最多 50 份输入文件**作为原型目标；总页数、总字节数、临时空间与内存上限由引擎原型在目标手机上实测后冻结。图片工具的“500 张”不能直接套用为 PDF 文件数或页数上限，界面需分别显示文件数和总页数。

### 3.3 页面与内容保留规则

- 保留各页自己的尺寸、页框及旋转，允许横竖页、A4、A5 和自定义尺寸混合。
- 保留支持范围内的文字、字体、矢量和图片；文字型 PDF 合并后仍应能搜索和复制文字。
- 合并页不套用图片转 PDF 的 A4、边距、裁切、DPI、JPEG 质量或额外页码设置；原页面上已有的印刷页码保持原样。
- 不把 PDF 逐页截图后重新生成图片 PDF，不把文件字节直接拼接当作 PDF 合并。
- 输出大小不承诺等于输入大小之和，也不把内容保留承诺扩写成文件逐字节不变或 PDF/A / PDF/UA 认证。

### 3.4 首版边界与错误处理

| 输入或情况 | 第一版计划行为 |
| --- | --- |
| 普通静态 PDF | 纳入支持范围，全部页面按顺序合并 |
| 加密 / 需要密码 | 首版明确提示暂不支持；密码解锁另行规划 |
| 数字签名 PDF | 首版检测后阻止合并并解释，新文档不能继承原签名的有效性 |
| 交互表单、XFA、组合文档或复杂附件 | 在引擎试验中检测并定义支持表；未支持类型先拒绝，不静默丢弃 |
| 注释、超链接、书签、标签结构 | 逐项验证；未能安全保留的文档类型必须明确提示和限制，不能只看视觉正常就宣称完整兼容 |
| 损坏、截断、零页或伪装文件 | 定位具体条目并阻止开始；不静默跳页或交付部分合并结果 |
| URI 撤权、源被删除、云文件未就绪 | 提示重新选择或等待提供方可用，保留其他草稿项 |
| 空间或内存预算不足 | 开始前明确拒绝；运行中失败清理本次半成品，保留输入草稿和旧完整结果 |
| 取消或进程中断 | 清理本次 `.partial`；恢复后显示中断，从头重试，不宣称断点续写 |

页范围、抽取 / 删除单页、单页重排、PDF 压缩、OCR、批量任务、密码处理和高级 PDF 编辑放到后续版本。

## 4. PDF 合并引擎与工程设计

现有 `StreamingPdfWriter` 只接收已编码的 JPEG 页，继续用于图片转 PDF。新增独立的 `PdfMergeEngine` 负责读取 PDF 并复制页面及关联资源。

Android `PdfRenderer` 用于缩略图和结果预览。官方文档也提供较新 API 的保存能力，但本项目不能把它当作覆盖最低 API 26 的跨文档页面复制方案。[Android PdfRenderer 文档](https://developer.android.com/reference/android/graphics/pdf/PdfRenderer)

### 4.1 先做引擎可行性验证

- 评估支持 PDF 页面复制、Android 运行和离线处理的引擎，封装在接口后，UI 不绑定具体库。
- Apache PDFBox 官方列有合并能力并采用 Apache 2.0；Android 移植项目 PdfBox-Android 可作候选，但其 README 仍声明基于 PDFBox 2.0.27。实施前必须核对维护状态、依赖安全、Android 兼容、许可与第三方 NOTICE，不能直接照旧版本示例接入。[Apache PDFBox](https://pdfbox.apache.org/)、[PdfBox-Android 项目](https://github.com/TomRoush/PdfBox-Android)
- 不在现有免费应用中未经评估引入 AGPL 或商业授权依赖；候选不通过时，明确记录替代方案与授权成本。
- 验证临时文件缓存、取消边界与资源释放。页面复制仍可能累积字体和其他对象，不能因为不使用大位图就断言恒定内存。
- URI 不可 seek 时受控缓存到私有目录；禁止把全部输入和输出装进一个大字节数组。限制读取量和临时空间，不依赖文件扩展名判断有效性。
- 不执行 PDF 脚本或主动加载外部附件和网络资源；新增功能不需要整盘访问或联网权限。

### 4.2 建议模块边界

| 部分 | 职责 |
| --- | --- |
| `app` | 百宝箱首页、导航，以及各工具独立的界面和状态 |
| 现有 `core` | 图片 PDF 布局与流式 JPEG 页写入，保留既有测试 |
| `pdf-merge` | PDF 引擎适配、输入检查、页面复制与结果校验 |
| `shuffle-core` | 从旧应用提取纯 Kotlin Gilbert 算法及对照测试 |
| 公共 Android 能力 | URI 授权、受控缓存、结果导出、任务协调、通知与错误展示 |

按阶段提取公共代码，不一次性重写全部工程。公共结果契约使用文件引用、任务 ID、类型及元数据，不在导航参数里传大 Bitmap。

## 5. 解混淆应用整合及数据兼容

### 5.1 安装身份与签名

推荐让百宝箱作为当前 PDF 应用的后续升级：沿用 **`cn.local.imagepdf` 和当前 1.0.4 发布密钥**，递增 versionCode，再将展示名改为“l君の百宝箱”。不为本计划提前更改版本或签名。覆盖升级前必须实际比对证书并验证草稿 / PDF 保留。[Android 应用签名](https://developer.android.com/studio/publish/app-signing)

另一个 `com.fanqie.hunxiao` 是不同应用；一个 APK 不能同时成为两个不同包名的覆盖升级。旧解混淆应用可继续保留，用户保存的图片通过系统选择或明确分享导入百宝箱。Android 沙箱隔离不同应用的私有数据，不能承诺自动读取旧应用私有设置或未保存图片。[Android 应用沙箱](https://source.android.com/docs/security/app-sandbox)

1.0.3 及更早调试签名与当前发布签名是不同的升级边界；本计划不以卸载旧应用作为默认数据迁移方案。涉及旧版本时先保护可导出结果，再设计和核验迁移路径。

### 5.2 保护草稿、授权和结果

- 保留现有图片草稿与完整 PDF；合并工具增加独立、带格式版本的草稿，不覆盖 `session.json`。
- 为每个工具和活跃任务登记源文件、URI 授权及临时文件引用。清理只能作用于已无引用且符合保留期的内容。
- **PDF 合并首次进入现有应用前（M1 前）必须修正授权清理边界**：现有 `ImageRepository.releaseUnusedSources()` 以图片草稿列表检查应用全部持久 URI 授权，可能释放合并草稿仍需要的授权。需先统一引用登记或隔离清理范围，并通过“图片清理不撤销合并授权”回归，不能等到百宝箱 M2 才处理。
- 原有完整结果不因切换工具、新建另一类任务或清缓存而被删除；用户选择的外部原文件不覆盖、不删除。
- 任务通知携带工具类型和任务 ID，返回与取消作用于正确任务。
- FileProvider 只开放所需结果 / 分享子目录，不开放整个私有目录或全部缓存。

### 5.3 保留解混淆的处理语义

- 解混淆依赖原像素尺寸和顺序，不能直接使用会采样缩放的图片转 PDF 管线。
- 旧解混淆透明区域合成黑底，图片 PDF 合成白底，两套规则分别保留并在界面说明。
- 原有 PNG / JPEG 保存和分享、处理取消、重置与进度继续保留；内存上限不能因合并工具增多而放宽。
- PDF 最低 API 26 与旧解混淆 API 29 存在差异。优先保持百宝箱的 API 26 要求，为旧版图片解码和保存补兼容分支；若兼容验证不通过，单独明确该工具的系统限制，不悄然提高整个应用门槛。
- 统一 JVM / Kotlin / Compose 配置后迁移算法，保留 Gilbert 的 BSD-2-Clause 归属与完整通知。
- “解混淆”继续指图片像素还原，不作为 PDF 密码处理功能命名。

后续可加入“解混淆结果 → 图片转 PDF”和“生成的 PDF → PDF 合并”快捷入口；必须由用户明确触发，不能自动修改其他工具草稿。

## 6. 实施阶段与建议版本

M0 / M1 本次实现版本冻结为 1.1.0 / code 6；M2 及后续版本仍为规划建议。手机实际安装版本与签名见测试报告。

| 阶段 | 交付内容 | 进入下一阶段的条件 |
| --- | --- | --- |
| M0 引擎试验与来源治理 | PDF 支持表、候选依赖与许可记录、资源预算、输入规模上限，以及图片 / 合并来源引用治理 | 样本通过独立验证，复杂类型处理明确；图片清理不撤合并草稿授权的回归通过后才进入 M1 |
| M1 PDF 合并，建议 1.1.x | 独立页面、文件排序、合并、预览、保存、分享、取消与草稿恢复 | 合并验收、双工具草稿和授权保护通过，现有图片功能无回归 |
| M2 百宝箱骨架 | 首页与独立导航，将已完成的来源治理扩展到三个工具，统一任务协调与通知 | 切换工具不丢草稿，不误撤授权或清理其他工具文件 |
| M3 解混淆整合，建议 2.0.x | 迁移已存在的单图功能，统一正式名称与主题，验证 API 兼容 | 算法对照、保存分享、内存和升级保留全部通过 |
| M4 后续增强 | 跨工具快捷入口、页范围与单页整理、按需求再加批量能力 | 在前三阶段稳定后逐项实现 |

不先承诺固定工期；M0 完成并取得真实手机指标后，再给 M1～M3 的可执行排期。

## 7. 验收清单

| 类别 | 必须取得的证据 |
| --- | --- |
| 合并正确性 | A/B/C 唯一编号样本的总页数与全部页序正确；混合尺寸、页框和旋转保持；文字可提取，矢量没有变成低清图片 |
| 文档兼容 | 独立解析器逐页检查，独立渲染对比原页与输出页；注释 / 链接 / 书签按支持表验证，密码、签名与不支持表单有明确阻止行为 |
| 规模与资源 | 按文件数、总页数和字节数分别测量，例如 2 / 10 / 50 份、100 / 500 / 1000 页；这些是测试矩阵，不是提前承诺的支持上限 |
| 真机稳定性 | 较新设备与 4 GB 设备上记录 Java / native / PSS / RSS、文件描述符、时间和输出大小；采样峰值与连续真实峰值分开标注 |
| 异常与取消 | 读取、复制、最终保存各阶段取消；源失效、空间不足、坏文档、进程中断及后台限制下的状态与半成品清理 |
| 百宝箱隔离 | 三种草稿互不覆盖；运行任务正确返回与取消；清理图片缓存不会撤销 PDF 合并授权或删除其源文件 |
| 解混淆回归 | 网站对照向量、奇偶尺寸、混淆再还原、PNG 保存再导入、透明黑底与不缩放规则、低内存和取消行为 |
| 现有功能 | 应用内全选、单批 500 张、排序 / 旋转、页面设置、取消与另存继续可用；旧报告不替代整合后的回归 |
| 安装升级 | 使用当前发布密钥从现有 PDF 应用升级后，草稿、完整 PDF 与设置仍在；旧解混淆数据仅通过用户授权路径接入 |
